# Rules in Code, Not in Context

**Rule:** If a rule must always happen, it is not a prompt. It is a hook.

**Why:** Instructions living in the chat fade in quality as the chat grows — that is context rot. A hook attaches to every prompt, scores every reply, and tells the next one what slipped. That is self-correcting.

**In practice:**
- Bucket every rule: always-happens → hook; state → a file only a script can write; procedure → skill; judgment → the project instructions.
- If nobody is checking the reply, it is not a rule.
- A skill you have to remember to invoke is a rule that decays.
